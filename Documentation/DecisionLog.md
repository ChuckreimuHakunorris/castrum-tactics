# Decision log

The linked records carry the original rationale and evidence. Add durable decisions here when accepted, and keep the detailed evidence in the owning architecture article or milestone report. Use the [roadmap](DevelopmentRoadmap.md) for status and the [game design](GameDesign.md#12-open-decisions-and-questions) for unresolved design choices.

| Status | Context and decision | Rationale and consequence |
| --- | --- | --- |
| Accepted | Use Godot .NET with C# and the Compatibility renderer for Windows and Android. | C# keeps domain rules shareable and testable independently of Godot. Desktop and Android require separate export verification. [Technology stack](GameDesign.md#22-intended-platforms-and-technology-direction) |
| Accepted | Keep rules in the engine-independent Domain assembly and coordinate local play through `IGameSession`. | Local modes share the authoritative rules. A future remote adapter can preserve the presentation boundary, and its protocol and authority model remain open. [Session architecture](SessionArchitecture.md) |
| Accepted | Publish immutable snapshots containing the resolved state and submitted flags. The session owns pending choices and round identity. | Both actors evaluate the same board. A stale command must be rejected within its session, and the worker validates session identity as well as round ID. [CPU worker lifecycle](CpuArchitecture.md#milestone-8b-integration-lifecycle) |
| Accepted | Resolve choices simultaneously against one pre-turn board and classify territory with conservative eight-connected components. | Placement and scoring share one resolved state. Conservative classification leaves unsettled regions contested until they are secured. [Main-phase rules](MainPhaseArchitecture.md) |
| Accepted; default superseded | Knight Support is official. Classic remains available as a legacy ruleset. | Starting castles and adjacency support change openings and knight survival. The retained ruleset supports historical playback and comparison. [Ruleset rationale](GameDesign.md#55-knight-support-ruleset) |
| Accepted | Keep frozen opponents, exact solver and experimental studies in Benchmarks. | The game stays independent of research tooling. Frozen opponents control for AI changes while sharing live Domain, so domain histories are verified separately. [Frozen controls](CpuBenchmarks.md#frozen-controls-and-provenance) · [9A evidence](ArchitectureRefactoring.md) |
| Accepted | Ship the 8E ladder with resilient Very Hard and Monster's separate advanced draft and numerical Main policy. | The selected pair limits balance measured search work and match evidence. Compact weaknesses, the Easy/Normal ordering on some starts and device performance remain open. [8E selection](CpuDifficultyCalibration.md) |
| Accepted | Split ownership conservatively in 9A and retain the cohesive renderer and code-built match dialog. | Centralizing shared calculations and lifecycle reduces drift. Separate draft search accounting and layout behavior are preserved to avoid changing outputs. [9A refactoring decisions](ArchitectureRefactoring.md) |
| Implemented in 9C | Pin one .NET SDK feature band and enforce scoped compiler, formatting, documentation and historical-integrity checks. | CI repeats routine local checks while existing archive bytes, experimental controls and optional device measurements retain separate verification requirements. [Engineering verification](EngineeringVerification.md) |
| Implemented in 10A | Keep optional visual map data in sidecars and publish resolved turns through the live session. | Sidecars preserve map and research identity. The session already owns the validated pair and can share both choices after resolution without changing preview contracts or exposing pending actions. [Visual architecture](VisualArchitecture.md) |
| Implemented in 10B | Pair fixed terrain art roles with the original gameplay cells and join only same-faction cardinal castles. | Sidecars preserve map identity. Intact ground stays free of persistent marks. [Visual architecture](VisualArchitecture.md) |
| Implemented in 10C | Use perspective-dependent faction frames, neutral draft shields and a static cyan provisional frame. | The session owns both legal sets. Opposing indicators are informational and remember the player’s display preference. [Visual architecture](VisualArchitecture.md#legal-targets-and-resolved-turns) |
| Implemented in 10C | Use secured plus contested territory for the banner denominator and persist independent motion and resolution preferences. | Numeric scores update immediately. Draft starts empty and reduced-motion fills update immediately. [Interaction verification](InteractionVerification.md) |
| Implemented in 10C.0 | Record opt-in native rendering evidence before refining assets or optimizing the renderer. | Use resolved production scenes and versioned synthetic fixtures. Keep software-renderer comparisons separate from device baselines. [Rendering benchmarks](RenderingBenchmarks.md) |
| Approved in the 10C.0 review | Hide ground-health marks on permanent castles and graves, and keep terrain wear underneath. | Keep the original extreme damage benchmark and add a reachable representative case. Use ordinary CPU decisions by default. [Review measurements](RenderingBenchmarks.md#pr-30-review-follow-up-scenario-version-2) |
| Accepted in the 10C.0 closure | Proceed with artwork refinement. Investigate incremental sprite synchronization first in 10C.2. | The native baseline is satisfactory at approximately 60 Hz. Android slow frames cluster around turn resolution. Measure the specific costs in isolation before selecting an optimization. [Native results](NativeRenderingBaseline.md) · [10C.2 priorities](VisualDevelopmentRoadmap.md#10c2--evidence-driven-rendering-optimization) |
